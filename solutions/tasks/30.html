Question

Say $\Pi = (\mathsf{Gen}, \mathsf{Mac}, \mathsf{Vrfy})$ is a secure MAC, and for $k \in \{0,1\}^n$ the tag-generation algorithm $\mathsf{Mac}_k$ always outputs tags of length $t(n)$. Prove that $t$ must be super-logarithmic.

Hint: Show $t(n) = \mathcal{O}(\log n) \Rightarrow \Pi$ is not a secure MAC.

Claim. If $t(n) \le c \log n$ for some constant $c$ and all large $n$, then $\Pi$ is not existentially unforgeable.

Attack: guess the tag

$\mathcal{A}$Make no oracle queries. Pick any message $m$, e.g. $m = 0^n$, choose $t \leftarrow \{0,1\}^{t(n)}$ uniformly, and output $(m, t)$.

$m$ was never queried, so $(m, t)$ counts as a forgery if it verifies.

Success probability

By correctness, the real tag $\mathsf{Mac}_k(m)$ always verifies. It is one of the $2^{t(n)}$ strings of length $t(n)$. Even if $\mathsf{Mac}$ is randomised, summing over the possible tags $\tau$:

$$\Pr[\mathsf{Vrfy}_k(m, t) = 1] \ \ge\ \sum_{\tau} \Pr[\mathsf{Mac}_k(m) = \tau] \cdot \Pr[t = \tau] = 2^{-t(n)} \ge 2^{-c \log n} = \frac{1}{n^c}.$$

So $\Pr[\mathsf{Mac\text{-}forge}_{\mathcal{A},\Pi}(n) = 1] \ge n^{-c}$, which is not negligible (Question 17, 4b). Hence $\Pi$ is not secure. $\blacksquare$

By contraposition, a secure MAC needs $t(n) = \omega(\log n)$: for every constant $c$, $t(n) \gt c \log n$ for all large $n$. Otherwise $2^{-t(n)}$ is at least an inverse polynomial.

In practice this is why tags are at least 64–128 bits long. A 16-bit tag can be guessed with probability $2^{-16}$ per try.

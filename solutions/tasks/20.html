Question

Let $F$ be a pseudorandom function, and $G$ a pseudorandom generator with expansion factor $\ell(n) = n + 1$. For each of the following encryption schemes, state whether the scheme has indistinguishable encryptions in the presence of an eavesdropper and whether it is CPA-secure, and justify your answer very briefly. In each case, the shared key is a random $k \in \{0,1\}^n$.

  1. To encrypt $m \in \{0,1\}^{2n+2}$ parse $m$ as $m_1 \| m_2$ with $|m_1| = |m_2|$ and send $\langle G(k) \oplus m_1, G(k+1) \oplus m_2 \rangle$.
  2. To encrypt $m \in \{0,1\}^{n+1}$ choose a random $r \leftarrow \{0,1\}^n$ and send $\langle r, G(r) \oplus m \rangle$.
  3. To encrypt $m \in \{0,1\}^n$ send $m \oplus F_k(0^n)$.
  4. To encrypt $m \in \{0,1\}^{2n}$ parse $m$ as $m_1 \| m_2$ with $|m_1| = |m_2|$, then choose $r \leftarrow \{0,1\}^n$ at random, and send $\langle r, m_1 \oplus F_k(r), m_2 \oplus F_k(r+1) \rangle$.

General facts used: CPA security implies EAV security, and a deterministic scheme is never CPA-secure. The attacker asks the oracle for the encryption of $m_0$ and compares it with the challenge.

1. Not EAV-secure in general, not CPA-secure

It is deterministic, so it is not CPA-secure. The PRG guarantee only covers one output on a uniform seed. It says nothing about $G(k)$ and $G(k+1)$ together, because the seeds $k$ and $k + 1$ are related.

Counterexample. Let $G'$ be a PRG from $n - 1$ to $n + 1$ bits, and let $G(s) := G'(s_1 \cdots s_{n-1})$, which ignores the last seed bit. $G$ is still a PRG. If the last bit of $k$ is $0$, then $k$ and $k + 1$ differ only in that bit, so $G(k) = G(k+1)$ and the two ciphertext halves satisfy $c_1 \oplus c_2 = m_1 \oplus m_2$.

Attack: choose $u \leftarrow \{0,1\}^{n+1}$ uniformly and output the messages $m^0 = 0^{n+1} \| 0^{n+1}$ and $m^1 = 0^{n+1} \| u$. Given $\langle c_1, c_2 \rangle$, output $0$ iff $c_1 = c_2$.

  • $b = 0$: $c_1 = c_2$ whenever $G(k) = G(k+1)$, so with probability at least $\frac12$.
  • $b = 1$: $c_1 \oplus c_2 = G(k) \oplus G(k+1) \oplus u$ with $u$ uniform and independent, so $c_1 = c_2$ only with probability $2^{-(n+1)}$.
$$\Pr[\mathsf{win}] \ge \tfrac12 \cdot \tfrac12 + \tfrac12 \big(1 - 2^{-(n+1)}\big) = \tfrac34 - 2^{-(n+2)}.$$

So the advantage is non-negligible.

2. Neither

$r$ is sent in the clear and $G$ is public, and the key $k$ is not even used. Anyone computes $G(r)$ and recovers $m = (G(r) \oplus m) \oplus G(r)$.

3. EAV-secure, not CPA-secure

EAV: this is a one-time pad with the pad $F_k(0^n)$. Since $F$ is a PRF, $F_k(0^n)$ is indistinguishable from a uniform string. So for a single message the scheme is as good as the one-time pad, up to a negligible difference: reduce to the PRF with a distinguisher that queries $0^n$ once.

Not CPA: the scheme is deterministic and always uses the same pad. Ask for $\mathsf{Enc}(0^n) = F_k(0^n)$ and decrypt the challenge with it.

4. EAV- and CPA-secure

This is randomised counter mode with two blocks: the pads are $F_k(r)$ and $F_k(r+1)$ for a fresh random $r$. Replace $F_k$ by a random function. The challenge pads are then uniform and independent of everything else unless one of the two inputs $r^*, r^* + 1$ was already used in an oracle query. With $q$ queries, that happens with probability at most $\frac{4q}{2^n}$, which is negligible. So the challenge is a one-time pad except with negligible probability, and the reduction to the PRF works as in Question 19.

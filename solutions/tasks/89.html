Question

Coin flipping with a trusted party $T$: $T$ publishes a public key $pk$. Party $A$ picks a random bit $b_A$ and announces $c_A \leftarrow \mathsf{Enc}_{pk}(b_A)$. Then $B$ announces a ciphertext $c_B \ne c_A$ of its bit $b_B$. Finally $T$ decrypts both and the coin is $b_A \oplus b_B$.

  1. Argue that the coin is uniform if $B$ is honest, even if $A$ cheats.
  2. With ElGamal (bit $b$ encoded as $g^b$), show that a dishonest $B$ can force the coin to any value.
  3. Which kind of encryption scheme should be used? Define a suitable security notion and prove that your suggestion achieves it.

Source: Katz & Lindell, 1st ed., Exercise 10.17 (restated).

(a) Honest $B$

$A$ commits to $c_A$ before $B$ chooses anything. Whatever $A$ does, $b_A := \mathsf{Dec}_{sk}(c_A)$ is a fixed value (treat $\bot$ as $0$). An honest $B$ then chooses $b_B$ uniformly and independently of $c_A$. For any fixed $b_A$, $b_A \oplus b_B$ is uniform, so the coin is uniform. $\blacksquare$

(b) Dishonest $B$ with ElGamal

ElGamal with $pk = (\mathbb{G}, q, g, h = g^x)$: $c_A = (g^y, h^y \cdot g^{b_A})$. ElGamal is homomorphic: multiplying ciphertexts component-wise multiplies the plaintexts, and inverting a ciphertext inverts its plaintext. $B$ does not know $b_A$, but it can still create ciphertexts that depend on it.

Force coin $= 0$: make $b_B = b_A$ by re-randomizing $c_A$. Choose $y' \leftarrow \mathbb{Z}_q$:

$$c_B = (g^{y} \cdot g^{y'},\; h^{y} g^{b_A} \cdot h^{y'}) = (g^{y+y'},\, h^{y+y'} g^{b_A}).$$

This is a fresh-looking encryption of $g^{b_A}$, and $c_B \ne c_A$ since $y' \ne 0$ (with probability $1 - 1/q$).

Force coin $= 1$: make $b_B = 1 - b_A$. Invert $c_A$ to get an encryption of $g^{-b_A}$, then multiply by an encryption of $g^1$:

$$c_B = (g^{-y} \cdot g^{y'},\; h^{-y} g^{-b_A} \cdot h^{y'} g) = (g^{y'-y},\, h^{y'-y} g^{1-b_A}).$$

$g^{1-b_A} \in \{g^0, g^1\}$ is a valid encoding, so $T$ decrypts $b_B = 1 - b_A$ and the coin is $1$. $B$ never learned $b_A$, but it chose the result. $\blacksquare$

(c) Use a non-malleable (CCA-secure) scheme

What is needed is that $B$ cannot produce a ciphertext whose plaintext is related to $A$'s hidden bit. This is non-malleability, and CCA security implies it.

Definition. The protocol is fair against $B$ if for every PPT strategy $B^*$, with $A$ honest:

$$\big|\Pr[\text{coin} = 1] - \tfrac12\big| \le \mathsf{negl}(n),$$

where $B^*$ sees $pk$ and $c_A$ and outputs any $c_B \ne c_A$; $T$ decrypts and a $\bot$ counts as $0$.

Claim. If the scheme is CCA-secure, the protocol is fair against $B$.

Proof. Suppose $B^*$ makes $\Pr[\text{coin} = \beta] \ge \frac12 + \varepsilon(n)$ for some $\beta$ and a non-negligible $\varepsilon$. Build a CCA adversary $\mathcal{D}$:

1.On $pk$: output the challenge messages $0$ and $1$; receive $c^* = \mathsf{Enc}_{pk}(b)$.
2.Run $B^*(pk, c^*)$ to get $c_B \ne c^*$, and ask the decryption oracle for $b_B = \mathsf{Dec}_{sk}(c_B)$. This is allowed since $c_B \ne c^*$.
3.Output $b' := \beta \oplus b_B$.

$c^*$ is distributed exactly like $A$'s $c_A$ with $b_A = b$ uniform, so

$$\Pr[b' = b] = \Pr[b \oplus b_B = \beta] = \Pr[\text{coin} = \beta] \ge \tfrac12 + \varepsilon(n),$$

which contradicts CCA security. (If the direction $\beta$ of the bias is unknown, run $\mathcal{D}$ for both values of $\beta$; one of the two adversaries has advantage $\varepsilon$.) $\blacksquare$

Result. (a) Committing first makes the coin uniform for an honest $B$. (b) ElGamal is malleable: re-randomizing or inverting $c_A$ lets $B$ copy or flip $A$'s bit without knowing it. (c) Use a CCA-secure (hence non-malleable) scheme; a biased coin would directly give a CCA attacker. $\blacksquare$

Encryption here is really used as a commitment. CPA security only gives hiding, while fairness also needs that no related commitment can be created.

Question

Consider the MAC $\mathsf{Mac}_k(m) := H(k \| m)$ for a function $H : \{0,1\}^* \to \{0,1\}^n$ and $k \in \{0,1\}^n$ (verification recomputes the tag). Show that it is secure when $H$ is modelled as a random oracle, but insecure when $H$ is any concrete hash function built with the Merkle–Damgård transform.

Source: Katz & Lindell, 1st ed., Exercise 13.3 (restated). The second part is Question 32.

Part 1: secure in the random oracle model

Let $\mathcal{A}$ make $q_H$ queries to $H$ and $q_M$ queries to $\mathsf{Mac}_k$, and output $(m^*, t^*)$ with $m^*$ never MAC-queried. Since $|k| = n$ is fixed, the string $k \| m$ determines $k$ and $m$ uniquely.

Let $\mathsf{KeyQuery}$ be the event that $\mathcal{A}$ queries $H$ on some string whose first $n$ bits are $k$.

$\Pr[\mathsf{KeyQuery}]$ is small. Couple the real game to a simulation with independent lazy-sampled hash answers and independent uniform MAC tags (cached for repeated messages). Before the first query with prefix $k$, this simulation and the real game agree. The simulated transcript is independent of $k$, so each of its at most $q_H$ candidate prefixes hits the uniform key with probability $2^{-n}$. The union bound gives

$$\Pr[\mathsf{KeyQuery}] \le q_H \cdot 2^{-n}.$$

Without $\mathsf{KeyQuery}$, forging means guessing. The tag $t^*$ is valid iff $t^* = H(k \| m^*)$. This point was never queried: not as a MAC query ($m^*$ is new), and not as an $H$-query (that would be $\mathsf{KeyQuery}$). So $H(k \| m^*)$ is uniform and independent of $t^*$:

$$\Pr[\mathsf{Mac\text{-}forge} = 1] \le \Pr[\mathsf{KeyQuery}] + 2^{-n} \le \frac{q_H + 1}{2^n},$$

which is negligible. $\blacksquare$

Part 2: insecure with Merkle–Damgård (length extension)

Merkle–Damgård (as in Question 69): pad $x$ with zeros to blocks $x_1, \dots, x_B$, append $x_{B+1} = |x|$, chain $z_i = h^s(z_{i-1} \| x_i)$ from $z_0 = 0^n$, and output $z_{B+1}$. The output is the internal chain value, so anyone holding $H(x)$ can continue the chain without knowing $x$.

1.Ask for the tag of some $m$: $t = H(k \| m) = z_{B+1}$. The length $L = n + |m|$ is known.
2.Let $\mathit{pad}$ be the zero-padding of $k \| m$. Choose any block $w$ and set $$m^* := m \,\|\, \mathit{pad} \,\|\, \langle L \rangle \,\|\, w.$$ Then $k \| m^*$ consists of the blocks $x_1, \dots, x_B, \langle L \rangle, w$, followed by its own length $L^* = L + |\mathit{pad}| + 2n$.
3.The chain of $k \| m^*$ passes through $z_{B+1} = t$ after the first $B+1$ blocks, so its output is $$t^* = h^s\big(h^s(t \| w) \,\|\, \langle L^* \rangle\big),$$ which the adversary can compute. Output $(m^*, t^*)$.

$m^* \ne m$ (it is longer), and the tag is valid with probability $1$. $\blacksquare$

Result. With a random oracle, $H(k \| m)$ is a fresh random value for each $m$ unless the adversary guesses $k$, so the MAC is secure. A Merkle–Damgård hash outputs its internal state, so $H(k \| m)$ can be extended to $H(k \| m \| \mathit{pad} \| L \| w)$ without the key. Here the random oracle model gives a wrong security verdict, which is why HMAC uses two nested hash calls. $\blacksquare$

Question

Consider the MAC $\mathsf{Mac}_k(m) := H(k \| m)$ for a function $H : \{0,1\}^* \to \{0,1\}^n$ and $k \in \{0,1\}^n$ (verification recomputes the tag). Show that it is secure when $H$ is modelled as a random oracle, but insecure when $H$ is any concrete hash function built with the Merkle–Damgård transform.

Source: Katz & Lindell, 1st ed., Exercise 13.3 (restated). The second part is Question 32.

Part 1: secure in the random oracle model

Let $\mathcal{A}$ make $q$ queries to $H$ and output $(m^*, t^*)$ with $m^*$ never MAC-queried. Let $\mathsf{KeyQuery}$ be the event that $\mathcal{A}$ queries $H$ on a string starting with $k$.

  • Until $\mathsf{KeyQuery}$ happens, $\mathcal{A}$'s view (random oracle answers and MAC tags, which are fresh random values for new messages) is independent of $k$. So each of its $q$ queries starts with $k$ with probability $2^{-n}$, and $\Pr[\mathsf{KeyQuery}] \le q \cdot 2^{-n}$.
  • Without $\mathsf{KeyQuery}$, the point $k \| m^*$ was never queried, so $H(k \| m^*)$ is uniform and $t^*$ is correct with probability $2^{-n}$.
$$\Pr[\mathsf{Mac\text{-}forge} = 1] \le \frac{q + 1}{2^n}, \quad\text{which is negligible.} \qquad \blacksquare$$

Part 2: insecure with Merkle–Damgård

Merkle–Damgård outputs its internal chain value, so anyone holding $H(x)$ can keep hashing (length extension). Write $\langle i \rangle$ for the $n$-bit encoding of $i$ and $z_0 = IV$.

1.Ask for the tag of a one-block message $m \in \{0,1\}^n$. Since $k \| m$ has two blocks and length $2n$: $t = h^s\big(h^s(h^s(IV \| k) \| m) \,\|\, \langle 2n \rangle\big)$.
2.Output the message $m^* := m \| \langle 2n \rangle$ with the tag $t^* := h^s(t \| \langle 3n \rangle)$.

$k \| m^*$ has the three blocks $k, m, \langle 2n \rangle$ and length $3n$, so its hash is $h^s\big(h^s(h^s(h^s(IV \| k) \| m) \| \langle 2n \rangle) \,\|\, \langle 3n \rangle\big) = h^s(t \| \langle 3n \rangle) = t^*$. The forgery is valid with probability $1$, and $m^* \ne m$. $\blacksquare$

Here the random oracle model gives the wrong verdict for concrete hash functions, which is why HMAC uses two nested hash calls.

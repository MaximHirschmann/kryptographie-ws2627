Question

Formally define the key-exchange experiment $\mathsf{KE}^{\mathsf{eav}}_{\mathcal{A},\Pi}(n)$ and its security in the presence of an eavesdropper.

Let $\Pi$ be a key-exchange protocol between two parties and $\mathcal{A}$ an adversary. This is the definition from the lecture (handwritten notes, "The Key-Exch. Experiment").

Experiment $\mathsf{KE}^{\mathsf{eav}}_{\mathcal{A},\Pi}(n)$

1.$(\mathsf{trans}, k) \leftarrow \Pi.\mathsf{run}(1^n)$: the two parties run the protocol on input $1^n$. $\mathsf{trans}$ contains all messages sent; $k \in \{0,1\}^n$ is the key output by both parties.
2.$b \leftarrow \{0,1\}$
3.$k_0 \leftarrow \{0,1\}^n$ uniformly at random
4.$k_1 := k$  (so $b = 1$ means "real key", $b = 0$ means "random key")
5.$b' \leftarrow \mathcal{A}(\mathsf{trans}, k_b)$
6.output $1$ iff $b = b'$

Security

Definition. A key-exchange protocol $\Pi$ is secure in the presence of an eavesdropper if for all PPT adversaries $\mathcal{A}$ there is a negligible function $\mathsf{negl}$ such that $$\Pr\big[\mathsf{KE}^{\mathsf{eav}}_{\mathcal{A},\Pi}(n) = 1\big] \le \tfrac12 + \mathsf{negl}(n).$$

Correctness (implicit): both parties output the same key $k$, always or except with negligible probability.

The adversary does not merely have to compute the key: it must not even be able to distinguish the key from a random string. Only then can the key safely be used in a private-key scheme. Diffie–Hellman satisfies this definition if the DDH problem is hard. The protocol in Question 45 does not.

Question

In this method (encrypt and authenticate), encryption and message authentication are computed independently. That is, given a plaintext $m$, the sender transmits $\langle c, t \rangle$ where:

$$c \leftarrow \mathsf{Enc}_{k_1}(m) \quad \text{and} \quad t \leftarrow \mathsf{Mac}_{k_2}(m).$$

Show that if any message authentication code having unique tags is used in the encrypt-and-authenticate approach, the resulting combination is not CPA-secure.

Problem

With unique tags, every message has exactly one valid tag, so $\mathsf{Mac}_{k_2}$ is deterministic. The tag is computed on the plaintext and sent in the clear, so equal plaintexts give equal tags. This reveals when the same message is sent twice, regardless of how good $\mathsf{Enc}$ is.

CPA attack

1.Choose two different messages $m_0 \ne m_1$ of equal length. Query the encryption oracle on $m_0$ and receive $\langle c, t_0 \rangle$ with $t_0 = \mathsf{Mac}_{k_2}(m_0)$.
2.Output the challenge pair $m_0, m_1$ and receive $\langle c^*, t^* \rangle$ with $t^* = \mathsf{Mac}_{k_2}(m_b)$.
3.Output $b' = 0$ if $t^* = t_0$, otherwise $b' = 1$.

Analysis

  • $b = 0$: $t^* = \mathsf{Mac}_{k_2}(m_0) = t_0$, since the tag is unique. The attacker is always right.
  • $b = 1$: the attacker is wrong only if $\mathsf{Mac}_{k_2}(m_1) = \mathsf{Mac}_{k_2}(m_0)$. That can only happen with negligible probability. Otherwise, after one query on $m_0$, an adversary could output $(m_1, t_0)$ as a forgery, which contradicts the security of the MAC.
$$\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A}}(n) = 1] \ \ge\ \tfrac12 \cdot 1 + \tfrac12 \big(1 - \mathsf{negl}(n)\big) = 1 - \mathsf{negl}(n). \qquad \blacksquare$$

A secure MAC protects integrity, not secrecy. A MAC tag may even reveal parts of the message. The recommended combination is encrypt-then-MAC: $t \leftarrow \mathsf{Mac}_{k_2}(c)$.

Question

In this method (encrypt and authenticate), encryption and message authentication are computed independently. That is, given a plaintext $m$, the sender transmits $\langle c, t \rangle$ where:

$$c \leftarrow \mathsf{Enc}_{k_1}(m) \quad \text{and} \quad t \leftarrow \mathsf{Mac}_{k_2}(m).$$

Show that if any message authentication code having unique tags is used in the encrypt-and-authenticate approach, the resulting combination is not CPA-secure.

Idea. With unique tags, $\mathsf{Mac}_{k_2}$ is deterministic. The tag is computed on the plaintext and sent in the clear, so equal plaintexts give equal tags.

CPA attack

1.Query the encryption oracle on $m_0$ and receive $\langle c, t_0 \rangle$ with $t_0 = \mathsf{Mac}_{k_2}(m_0)$.
2.Output $m_0, m_1$ ($m_0 \ne m_1$) and receive $\langle c^*, t^* \rangle$.
3.Output $0$ iff $t^* = t_0$.

For $b = 0$, $t^* = t_0$ always. For $b = 1$, $t^* = t_0$ would mean $\mathsf{Mac}_{k_2}(m_1) = \mathsf{Mac}_{k_2}(m_0)$, i.e. $(m_1, t_0)$ would be a forgery; by MAC security this has negligible probability. So the attacker wins with probability $1 - \mathsf{negl}(n)$. $\blacksquare$

A MAC protects integrity, not secrecy. Use encrypt-then-MAC: $t \leftarrow \mathsf{Mac}_{k_2}(c)$.

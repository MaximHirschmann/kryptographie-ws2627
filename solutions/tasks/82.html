Question

Describe a man-in-the-middle attack on Diffie–Hellman key exchange in which the attacker ends up sharing a key $k_A$ with Alice and a different key $k_B$ with Bob, without Alice or Bob noticing anything. What happens if Alice and Bob try to detect the attacker by sending each other (encrypted) questions that only the real partner can answer?

Source: Katz & Lindell, 1st ed., Exercise 9.2 (restated).

The attack

Eve runs two independent, honest Diffie–Hellman executions: one with Alice, playing Bob, and one with Bob, playing Alice.

1.Alice sends $g^a$. Eve keeps it and sends $g^{e_1}$ to Bob instead.
2.Bob sends $g^b$. Eve keeps it and sends $g^{e_2}$ to Alice instead.
3.Alice outputs $k_A = g^{a e_2}$ and Bob outputs $k_B = g^{b e_1}$. Eve computes both: $k_A = (g^a)^{e_2}$, $k_B = (g^b)^{e_1}$.

Eve then decrypts every message with one key and re-encrypts it with the other. Each party ran a correct protocol execution with someone, so neither can detect anything: the DH messages are not authenticated.

Secret questions do not help

Eve simply relays them: she decrypts Alice's question with $k_A$, re-encrypts it with $k_B$, and does the same with Bob's answer. The real Bob answers, so Alice gets the right answer, and Eve learns it too. Only authentication bound to the exchanged values (e.g. signatures on $g^a, g^b$ under certified keys) prevents the attack. $\blacksquare$

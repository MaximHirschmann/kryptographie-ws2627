Question

Consider a variant of CBC-mode encryption where the sender simply increments the $IV$ by 1 each time a message is encrypted (rather than choosing $IV$ at random each time). Show that the resulting scheme is not CPA-secure.

Recall CBC

$c_0 := IV$ and $c_i := F_k(c_{i-1} \oplus m_i)$. The ciphertext is $\langle IV, c_1, \dots, c_\ell \rangle$, so the IV is public. In this variant, the next IV is always the previous IV plus 1, so the attacker can predict it.

Attack

Single-block messages are enough.

1.Query the encryption oracle on $m = 0^n$. The answer is $\langle IV, c \rangle$ with $c = F_k(IV \oplus 0^n) = F_k(IV)$.
2.The challenge will use $IV' = IV + 1$. Choose $$m_0 := IV \oplus (IV + 1), \qquad m_1 := m_0 \oplus 0^{n-1}1 \ (\text{any other message}).$$
3.Receive $\langle IV', c^* \rangle$ with $c^* = F_k(IV' \oplus m_b)$.
4.Output $b' = 0$ if $c^* = c$, otherwise $b' = 1$.

Analysis

  • $b = 0$: $IV' \oplus m_0 = (IV + 1) \oplus IV \oplus (IV + 1) = IV$, so $c^* = F_k(IV) = c$. The attacker answers $0$ and is right.
  • $b = 1$: $IV' \oplus m_1 = IV \oplus 0^{n-1}1 \ne IV$. $F_k$ is a permutation, so $c^* \ne c$. The attacker answers $1$ and is right.
$$\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A},\Pi}(n) = 1] = 1.$$

So the scheme is not CPA-secure. $\blacksquare$

The attacker chooses its challenge message so that it cancels the predictable IV. That way the block-cipher input is one it has already seen. CBC needs an unpredictable IV. A counter is enough for CTR mode, but not for CBC. (TLS 1.0 had this weakness, which led to the BEAST attack.)

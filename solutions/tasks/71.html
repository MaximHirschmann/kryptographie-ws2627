Question

Using Question 70:

  1. Show that for $k = 0^{56}$, $\mathsf{DES}_k(\mathsf{DES}_k(x)) = x$ for all $x$. Why is such a key a security risk?
  2. Find three other keys with this property (the weak keys of DES).
  3. Do these four weak keys make DES seriously vulnerable?

Source: Katz & Lindell, 1st ed., Exercise 5.9 (restated).

(a) The key $0^{56}$

Key schedule. The 56-bit key is split by $PC\text{-}1$ into two 28-bit registers $C_0, D_0$. In each round both are rotated left by 1 or 2 positions, and $PC\text{-}2$ selects 48 bits of $C_i \| D_i$ as sub-key $k_i$.

For $k = 0^{56}$: $C_0 = D_0 = 0^{28}$, rotating zeros gives zeros, so every $C_i, D_i$ is zero and every sub-key is $k_i = 0^{48}$.

By Question 70, $\mathsf{DES}_k^{-1}$ is DES with sub-keys in reverse order. Here all sub-keys are equal, so the reversed sequence is the same sequence: $\mathsf{DES}_k^{-1} = \mathsf{DES}_k$, i.e.

$$\mathsf{DES}_k(\mathsf{DES}_k(x)) = x \quad \text{for all } x.$$

Why it is dangerous.

  • Encryption decrypts: anyone who can get encryptions (a chosen-plaintext setting, e.g. a device that encrypts on request) can decrypt any ciphertext $c$ by asking for the encryption of $c$.
  • Double encryption is the identity: encrypting twice, e.g. in a protocol or a careless "double DES", sends the plaintext in the clear.
  • Easy to recognize: $\mathsf{DES}_k$ is an involution, so it is trivially distinguishable from a random permutation, for which $\pi(\pi(x)) = x$ almost never holds.

(b) Three more weak keys

The argument only needed that both registers are constant, i.e. all-zero or all-one, since rotation leaves them unchanged. That gives four combinations:

$C_0$$D_0$Key with parity bits (hex)
$0^{28}$$0^{28}$01 01 01 01 01 01 01 01
$1^{28}$$1^{28}$FE FE FE FE FE FE FE FE
one all-zero, the other all-one1F 1F 1F 1F 0E 0E 0E 0E and E0 E0 E0 E0 F1 F1 F1 F1

(In the 64-bit form every 8th bit is a parity bit, which is why the bytes are not simply 00/FF. $PC\text{-}1$ scatters the key bits, so the two mixed keys are not the obvious "half zeros, half ones" strings.)

In each case all 16 sub-keys are equal, so the same argument gives $\mathsf{DES}_k \circ \mathsf{DES}_k = \mathrm{id}$.

(c) Is this a serious vulnerability?

No. A uniformly random key is weak with probability $4/2^{56} = 2^{-54}$, which is extremely small. DES has a fixed key length, so “negligible” here would be informal, not the asymptotic definition from Question 17. Implementations can also simply reject these four keys when generating a key. They matter only when keys are not chosen at random, e.g. if an attacker can choose or influence the key, or when DES is used as a building block whose key is derived from data, as in Question 75.

Result. Keys whose two key-schedule registers are constant give 16 identical sub-keys, so $\mathsf{DES}_k$ is its own inverse. There are exactly four such keys. They are dangerous when used, but a random key hits one with probability $2^{-54}$. $\blacksquare$

There are also 6 pairs of semi-weak keys with $\mathsf{DES}_{k_1} = \mathsf{DES}_{k_2}^{-1}$, where the registers have alternating patterns like $0101\ldots$.

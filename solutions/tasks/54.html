Question

Let $\Pi$ be a public encryption scheme having indistinguishable encryptions under a chosen-plaintext attack. Let $\Pi'$ be a private-key encryption scheme having indistinguishable encryptions under a chosen-ciphertext attack.

Consider the following construction of a public-key encryption scheme $\Pi^*$. Let $H : \{0,1\}^n \to \{0,1\}^n$ be a function.

  • $\mathsf{Gen}^*$: input $1^n$; $(pk, sk) \leftarrow \mathsf{Gen}(1^n)$; output $(pk, sk)$
  • $\mathsf{Enc}^*$: input $pk$, $m \in \{0,1\}^n$; $r \leftarrow \{0,1\}^n$; output $\langle \mathsf{Enc}_{pk}(r), \mathsf{Enc}'_{H(r)}(m) \rangle$
  • $\mathsf{Dec}^*$: input $sk$, $\langle c_1, c_2 \rangle$; $r := \mathsf{Dec}_{sk}(c_1)$; output $\mathsf{Dec}'_{H(r)}(c_2)$

In what follows, assume that we model $H$ as a random oracle.

  1. Name a scheme $\Pi$ for which $\Pi^*$ has indistinguishable encryptions under a chosen-ciphertext attack.
  2. Does $\Pi^*$ have indistinguishable encryptions under a chosen-ciphertext attack in general? If yes then provide a proof. Otherwise, explain where a proof would break down.

1. A scheme $\Pi$ that works: RSA

Take plain RSA as the inner scheme: $pk = (N, e)$, $c_1 := [r^e \bmod N]$ for a uniform $r \in \mathbb{Z}_N^*$, and $\mathsf{Dec}_{sk}(c_1) = [c_1^{\,d} \bmod N]$. The resulting scheme

$$\Pi^*:\quad \langle [r^e \bmod N],\ \mathsf{Enc}'_{H(r)}(m) \rangle$$

is CCA-secure if RSA-invert is hard relative to $\mathsf{GenRSA}$, $\Pi'$ is IND-CCA secure, and $H$ is modelled as a random oracle. This is exactly the theorem "Security against CCA" from the lecture (Mitschrift 18.2), with $H : \mathbb{Z}_N^* \to \{0,1\}^n$.

Proof structure from the lecture. Let $\mathsf{query}$ be the event that $\mathcal{A}$ asks $H$ at the value $\hat r$ used for the challenge $\langle \hat c_1, \hat c_2 \rangle$. Then

$$\Pr[\mathsf{succ}] \le \Pr[\mathsf{succ} \wedge \overline{\mathsf{query}}] + \Pr[\mathsf{query}].$$
  1. $\Pr[\mathsf{succ} \wedge \overline{\mathsf{query}}] \le \frac12 + \mathsf{negl}(n)$, by a reduction $\mathcal{A}'$ in $\mathsf{PrivK}^{\mathsf{cca}}_{\mathcal{A}',\Pi'}$. $\mathcal{A}'$ runs $\mathsf{GenRSA}$ itself, chooses $\hat r$, sets $\hat c_1 := [\hat r^e \bmod N]$ and lets $H(\hat r)$ be implicitly the challenger's unknown key $\hat k$. Its decryption oracle answers $\langle c_1, c_2 \rangle$ with $\mathsf{Dec}'(c_2)$ from its own CCA oracle if $c_1 = \hat c_1$, and otherwise decrypts $r := [c_1^{\,d} \bmod N]$ itself and uses $H(r)$.
  2. $\Pr[\mathsf{query}] \le \mathsf{negl}(n)$, by a reduction in RSA-invert that gets $\hat c_1$ and must find $\hat r = [\hat c_1^{\,d} \bmod N]$ without $d$. Here it answers decryption queries using a table of entries $(r, c_1, k)$: for an unknown $c_1$ it stores $(*, c_1, k)$ with a fresh $k \leftarrow \mathsf{Gen}'(1^n)$ and answers with $\mathsf{Dec}'_k(c_2)$. When $\mathcal{A}$ later queries $H(r)$ with $[r^e \bmod N] = c_1$, the placeholder $*$ is replaced by $r$ and the same $k$ is returned, so the answers stay consistent. If $\mathcal{A}$ ever queries $H(\hat r)$, the reduction finds $\hat r$ in its table and outputs it.

Why RSA works here: the RSA function is a deterministic permutation, so every $c_1$ belongs to exactly one $r$, and the check $[r^e \bmod N] = c_1$ only needs the public key.

Any CCA-secure public-key scheme $\Pi$ (e.g. Cramer–Shoup) would also do, by the usual KEM/DEM composition.

2. Not in general

No. CPA security of $\Pi$ allows malleable ciphertexts. A CCA adversary can then turn the challenge $c_1$ into a different ciphertext $c_1'$ with the same $r$, and get $m_b$ from the decryption oracle.

Counterexample

Let $\hat\Pi$ be any CPA-secure scheme and define $\Pi$ by attaching an ignored bit:

$$\mathsf{Enc}_{pk}(r) := \langle \hat{\mathsf{Enc}}_{pk}(r),\ 0 \rangle, \qquad \mathsf{Dec}_{sk}(\langle \hat c, \beta \rangle) := \hat{\mathsf{Dec}}_{sk}(\hat c) \ \text{ (ignores } \beta).$$

$\Pi$ is still CPA-secure, because the extra bit is constant. Attack on $\Pi^*$:

1.Output $m_0 \ne m_1$ and receive the challenge $\langle c_1, c_2 \rangle$ with $c_1 = \langle \hat c, 0 \rangle$.
2.Query the decryption oracle on $\langle \langle \hat c, 1 \rangle, c_2 \rangle$. This differs from the challenge, so it is allowed.
3.The answer is $\mathsf{Dec}'_{H(r)}(c_2) = m_b$, with the same $r$. Output $b$.

It wins with probability $1$, so $\Pi^*$ is not CCA-secure. The random oracle and the CCA security of $\Pi'$ do not help, because the attacker never needs to know $H(r)$.

Where the proof breaks down

  • Simulating decryption queries. A reduction to the security of $\Pi$ only has CPA access: it does not have $sk$ and gets no decryption oracle. For a query $\langle c_1', c_2' \rangle$ with $c_1' \ne c_1$ it would have to compute $\mathsf{Dec}_{sk}(c_1')$ to know which $H(r')$ to use. For RSA this can be done by checking $(r')^e = c_1'$ over the oracle queries. For a general, randomised CPA-secure $\Pi$ there is no way to test whether $c_1'$ encrypts a given $r'$.
  • Queries related to the challenge. The reduction to $\Pi'$'s CCA security handles queries with the challenge key $H(r)$ only if they come with the same $c_1$. A different $c_1'$ that still decrypts to $r$ is exactly what the counterexample uses. Neither the CPA security of $\Pi$ nor the CCA security of $\Pi'$ rules this out.

Lesson: CCA security of the hybrid needs the key-encapsulation part to be non-malleable, e.g. CCA-secure itself, or uniquely checkable as with RSA in the random-oracle model.

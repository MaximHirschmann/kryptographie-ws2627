Question

Before HMAC was invented, it was quite common to define a MAC by $\mathsf{Mac}_k(m) = H^s(k \| m)$ where $H$ is a collision-resistant hash function. Show that this is not a secure MAC when $H$ is constructed via the Merkle-Damgård transform.

Merkle–Damgård

Let $h^s : \{0,1\}^{2n} \to \{0,1\}^n$ be a compression function. To hash $x$ of length $L$: pad $x$ with zeros to a multiple of $n$, split it into blocks $x_1, \dots, x_B$, and append the length block $x_{B+1} := L$. Then

$$z_0 := IV, \qquad z_i := h^s(z_{i-1} \,\|\, x_i) \ \ (i = 1, \dots, B+1), \qquad H^s(x) := z_{B+1}.$$

The output $z_{B+1}$ is the full internal state. Anyone who knows it can keep hashing more blocks without knowing $x$.

Length-extension attack

Let $|k| = n$, which is public.

1.Query the MAC oracle on any message $m$ and receive $t = H^s(k \| m) = z_{B+1}$.
2.Let $x = k \| m$ with $L = |x|$, and $\text{pad}$ the zeros that fill up the last block. Define the new message $$m^* := m \,\|\, \text{pad} \,\|\, \langle L \rangle \,\|\, y$$ for any block $y$. Here $\langle L \rangle$ is the length block written out.
3.Compute the tag without the key: $$t^* := h^s\big(h^s(t \,\|\, y) \,\big\|\, \langle L^* \rangle\big), \qquad L^* := |k \| m^*| = n + |m^*|.$$
4.Output the forgery $(m^*, t^*)$.

Why it is valid

Hashing $k \| m^*$ goes through the blocks $x_1, \dots, x_B$, then $\langle L \rangle$, then $y$, then the final length block $\langle L^* \rangle$. After the first $B + 1$ blocks the state is exactly $t$. The remaining two steps are what the attacker computed. So $\mathsf{Mac}_k(m^*) = t^*$. Since $m^* \ne m$ was never queried, this is a valid forgery with probability $1$. $\blacksquare$

Collision resistance does not help here, because no collision is used. The problem is that the tag reveals the internal state. HMAC prevents this with the outer hash: $H^s\big((k \oplus opad) \,\|\, H^s((k \oplus ipad) \| m)\big)$.

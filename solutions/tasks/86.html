Question

Two results from the book: Theorem 10.10 (single-message security implies multiple-message security for public-key encryption) and Proposition 10.11 (encrypting a long message bit by bit with a secure single-bit scheme $\Pi$ gives a secure scheme $\Pi'$). Show that Proposition 10.11 does not hold for CCA security, whereas Theorem 10.10 does. Explain why CPA security does not distinguish "many messages" from "one long message", but CCA security does.

Source: Katz & Lindell, 1st ed., Exercise 10.13 (restated).

Setting

$\Pi'$ encrypts $m = m_1 \cdots m_t$ as $\langle c_1, \dots, c_t \rangle$ with $c_i \leftarrow \mathsf{Enc}_{pk}(m_i)$, and decrypts component-wise. In $\mathsf{PubK}^{\mathsf{cca}}$ the adversary may ask for decryptions of anything except the challenge ciphertext itself.

Part 1: $\Pi'$ is not CCA-secure, even if $\Pi$ is

1.Output $m_0 = 0^t$ and $m_1 = 1^t$ (with $t \ge 2$); receive $c^* = \langle c_1, \dots, c_t \rangle$.
2.Compute a fresh $e \leftarrow \mathsf{Enc}_{pk}(0)$ and form $c' = \langle c_1, \dots, c_{t-1}, e \rangle$.
3.If $c' \ne c^*$, ask the decryption oracle for $\mathsf{Dec}(c')$; its first bit is $b$. Output it.

The query is allowed: $c' = c^*$ only if $e = c_t$. A CPA-secure $\Pi$ cannot produce the same ciphertext twice except with negligible probability: otherwise "compare the challenge with a fresh encryption of 0" would distinguish encryptions of 0 and 1. So $c' \ne c^*$ with overwhelming probability.

The answer reveals $b$: $\mathsf{Dec}(c') = (b, \dots, b, 0)$. The adversary wins with probability $1 - \mathsf{negl}(n)$. $\blacksquare$

The problem is malleability: components of the challenge can be cut out, reordered or recombined into a new, legal ciphertext. Each component is protected individually, but the vector is not protected as a whole.

Part 2: Theorem 10.10 holds for CCA

In the multiple-message CCA experiment the adversary outputs vectors $(m^1_0, \dots, m^t_0)$ and $(m^1_1, \dots, m^t_1)$, receives $\langle C^1, \dots, C^t \rangle$ with $C^i \leftarrow \mathsf{Enc}_{pk}(m^i_b)$, and may ask for the decryption of any ciphertext other than each $C^i$.

The usual hybrid argument works. Hybrid $H_j$ encrypts the first $j$ messages from vector $1$ and the rest from vector $0$. A reduction $\mathcal{A}'$ for neighbouring hybrids $H_{j-1}, H_j$:

  • it gets $pk$ and a decryption oracle for $\Pi$, and forwards the adversary's decryption queries to it;
  • it encrypts all positions $i \ne j$ itself (the public key suffices), and takes its own challenge for position $j$ with messages $(m^j_0, m^j_1)$;
  • the adversary may not ask for $C^j$, which is the only ciphertext $\mathcal{A}'$ itself may not ask for. So every query can be forwarded.

A distinguishing advantage $\varepsilon$ between $H_0$ and $H_t$ gives advantage $\varepsilon/t$ against $\Pi$. So single-message CCA security implies multiple-message CCA security. $\blacksquare$

Part 3: why the two notions differ only for CCA

  • CPA: the adversary sees exactly the same thing whether we call $\langle c_1, \dots, c_t \rangle$ "$t$ ciphertexts" or "one ciphertext of a long message", and has no oracle whose rules depend on that choice. The notions coincide.
  • CCA: the rule "you may not query the challenge" depends on what the challenge is. For $t$ separate ciphertexts, every $C^i$ is forbidden. For one long ciphertext, only the exact vector $c^*$ is forbidden, and vectors that reuse some of its components are allowed. This is exactly what Part 1 uses.
Result. Bit-by-bit encryption with a CCA-secure scheme is not CCA-secure: mix one challenge component with a fresh one and ask for decryption. Multiple-message security still follows from single-message security for CCA, because each individual challenge ciphertext stays forbidden. The difference comes from what counts as "the challenge" in the decryption-oracle restriction. $\blacksquare$

Question

Strengthen the MAC security definition so that the adversary gets oracle access to both $\mathsf{Mac}_k(\cdot)$ and $\mathsf{Vrfy}_k(\cdot, \cdot)$.

  1. Give the formal definition and explain which real-world attacks the $\mathsf{Vrfy}$ oracle models.
  2. Show: if $\Pi$ has unique tags, then $\Pi$ satisfies your definition whenever it satisfies the usual definition (Definition 4.2).
  3. Show: without unique tags, $\Pi$ may satisfy Definition 4.2 but not your definition.

Source: Katz & Lindell, 1st ed., Exercise 4.5 (restated).

(a) Definition

The experiment $\mathsf{Mac\text{-}forge}^{\mathsf{vrfy}}_{\mathcal{A},\Pi}(n)$:

1.$k \leftarrow \mathsf{Gen}(1^n)$.
2.$\mathcal{A}(1^n)$ gets oracles $\mathsf{Mac}_k(\cdot)$ and $\mathsf{Vrfy}_k(\cdot,\cdot)$. Let $\mathcal{Q}$ be the set of messages it asked $\mathsf{Mac}_k$ for.
3.$\mathcal{A}$ outputs $(m, t)$. The output is $1$ iff $\mathsf{Vrfy}_k(m, t) = 1$ and $m \notin \mathcal{Q}$.

$\Pi$ is secure with verification queries if for every PPT $\mathcal{A}$, $\Pr[\mathsf{Mac\text{-}forge}^{\mathsf{vrfy}}_{\mathcal{A},\Pi}(n) = 1] \le \mathsf{negl}(n)$.

What it models. In practice an attacker can send forged messages to the receiver and observe whether they are accepted: the receiver acts on the message, answers it, returns an error code, takes measurably longer, or closes the connection. Each such reaction answers one verification query.

(b) Unique tags make the $\mathsf{Vrfy}$ oracle useless

Unique tags: $\mathsf{Mac}_k$ is deterministic and $\mathsf{Vrfy}_k(m, t) = 1 \iff t = \mathsf{Mac}_k(m)$.

Let $\mathcal{A}'$ be a PPT adversary in the new experiment making at most $q_v$ verification queries. Build $\mathcal{A}$ for Definition 4.2 (only a $\mathsf{Mac}$ oracle):

1.Choose $j \leftarrow \{1, \dots, q_v + 1\}$.
2.Run $\mathcal{A}'$ and forward its $\mathsf{Mac}$ queries to the own oracle.
3.For a verification query $(m, t)$ with $m \in \mathcal{Q}$: the unique valid tag $\mathsf{Mac}_k(m)$ is already known, so answer $1$ iff $t$ equals it (always correct).
4.For a verification query $(m, t)$ with $m \notin \mathcal{Q}$ (a "fresh" query): if it is the $j$-th fresh query, stop and output $(m, t)$; otherwise answer $0$.
5.If $\mathcal{A}'$ finishes, output its final $(m, t)$ (this is "query number $q_v + 1$").

The simulation is perfect up to the first fresh verification query whose correct answer is $1$, because that query is itself a forgery. Let $i^*$ be the position of the first valid fresh query, or $q_v + 1$ if $\mathcal{A}'$ only succeeds with its final output. If $\mathcal{A}'$ succeeds or makes a valid fresh query, then $i^*$ exists, and with probability $\frac{1}{q_v+1}$ we have $j = i^*$. In that case $\mathcal{A}$ outputs a valid forgery on a message it never asked to be MACed. Therefore

$$\Pr[\mathsf{Mac\text{-}forge}^{\mathsf{vrfy}}_{\mathcal{A}',\Pi} = 1] \le (q_v + 1) \cdot \Pr[\mathsf{Mac\text{-}forge}_{\mathcal{A},\Pi} = 1] \le (q_v + 1) \cdot \mathsf{negl}(n),$$

which is negligible since $q_v$ is polynomial. $\blacksquare$

(c) Without unique tags: a counterexample

Let $\Pi = (\mathsf{Gen}, \mathsf{Mac}, \mathsf{Vrfy})$ be any secure MAC with $n$-bit keys (e.g. $\mathsf{Mac}_k(m) = F_k(m)$). Define $\Pi'$ with the same keys. The new tags are triples $(t, i, \beta)$ with $i \in \{0, \dots, n\}$ and $\beta \in \{0,1\}$:

Mac'$\mathsf{Mac}'_k(m) = (\mathsf{Mac}_k(m), 0, 0)$
Vrfy'$\mathsf{Vrfy}'_k(m, (t, i, \beta)) = 1$ iff $\mathsf{Vrfy}_k(m, t) = 1$ and ($i = 0$ or $k_i = \beta$)

Tags are not unique: $(t, 0, 0)$ and $(t, i, k_i)$ are all valid.

$\Pi'$ satisfies Definition 4.2. A forgery $(m^*, (t^*, i, \beta))$ for a fresh $m^*$ requires $\mathsf{Vrfy}_k(m^*, t^*) = 1$, which is a forgery against $\Pi$. A reduction simulates $\mathsf{Mac}'$ by appending $(0, 0)$ to its own tags. So any forger for $\Pi'$ gives a forger for $\Pi$ with the same success probability.

$\Pi'$ is broken with a $\mathsf{Vrfy}$ oracle.

1.Query $\mathsf{Mac}'_k(m)$ for some $m$ and get $(t, 0, 0)$.
2.For $i = 1, \dots, n$: query $\mathsf{Vrfy}'_k(m, (t, i, 0))$. The answer is $1$ iff $k_i = 0$, so it reveals bit $k_i$.
3.With the full key $k$, compute $(\mathsf{Mac}_k(m^*), 0, 0)$ for a new $m^* \ne m$ and output it.

This uses $1 + n$ queries and succeeds with probability $1$. $\blacksquare$

Result. With unique tags, a verification oracle gives nothing that the $\mathsf{Mac}$ oracle doesn't already give, except the chance to test forgeries, which is covered by guessing $j$. Without unique tags, "which tags are accepted" can leak secret information, as $\Pi'$ shows. $\blacksquare$
